# 安全边界声明

> 依据审计 9.3 节（功能范围真实性）与 9.12 节（失联降级与人工接管）要求编制。
> 本声明界定本 SCADA 系统**做什么、不做什么**，是设计、部署、验收与答辩的统一安全口径。

## 1. 系统职责边界

本系统（工业数据采集与监控系统，SCADA）仅承担以下四类职责：

1. **监视**：设备状态、工艺参数的实时采集与可视化
2. **数据采集**：历史数据存储、归档、导出
3. **告警**：越限报警、声光提示、广播通知、报警记录
4. **经授权的监督控制**：在满足第 3 节全部前提下的有限控制写入（启停、设定值调节）

本系统**不承担**任何安全相关控制功能。

## 2. 安全功能不依赖 SCADA

以下安全功能**必须**由 PLC / SIS（安全仪表系统）/ 现场安全系统独立完成，**不依赖**本 SCADA、不依赖网络、不依赖桌面端：

- **E-STOP（紧急停机）**：硬件急停回路，直接切断动力，不经过任何软件
- **硬联锁**：电气/机械联锁，继电器或安全 PLC 实现
- **保护逻辑**：过温、过压、超速等保护，由 PLC/SIS 本地执行
- **安全仪表功能（SIF）**：由 SIS 按 SIL 等级独立实现

即使 SCADA 完全失效、网络完全中断、桌面端全部关机，上述安全功能必须照常工作。这是验收的先决条件，不得以"SCADA 上有急停按钮"为由削弱硬件安全回路。

本系统中的软件急停（`DeviceControlSafety` 紧急停机、写阻止）只是**辅助手段**，不是安全回路的一部分。

## 3. 控制写入的前提条件

**默认禁止未经确认的远程写入。** 任何控制写入必须同时满足：

| 前提 | 实现位置 |
|---|---|
| 权限：操作者经认证且角色被授权 | `展示层/api/api_auth.py`（JWT）+ `智能层/device_control.py` 权限层 |
| 范围：目标设备、寄存器在许可清单内，只读寄存器不可写 | `RealDeviceManager.adjust_device` 寄存器 `access` 校验 |
| 联锁：通过联锁条件检查 | `DeviceControlSafety.check_interlocks` |
| 超时：操作有超时与未完成保护 | `DeviceControlSafety` 超时层 |
| 反馈：写入结果回读/回报，失败可见 | 写入路径返回 `success/message`，失败记日志与报警 |
| 审计：操作者、时间、目标、旧值/新值全程留痕 | `DeviceControlSafety` 操作审计（持久化、容量 50000 条） |

任何一环不满足，写入必须被拒绝且留痕。

## 4. "不支持" ≠ "安全"

某功能"不支持/未实现"只是意味着本系统**不提供**该能力，**绝不意味着**现场因此安全：

- DNP3 / IEC 104 / S7 主流程接入、OPC UA 写、协议级推送等不支持项，仅表示本系统不经这些链路动作；现场若存在这些链路，其安全由**现场设备自身与人工流程**承担
- 所有未覆盖的保护场景（工艺异常处置、设备本体保护、人员安全）均由 **PLC / SIS / 现场设备 / 操作规程** 承担，不在本系统责任范围内
- 验收时不得以"SCADA 没这功能"推断"风险不存在"

## 5. SCADA 失联时的降级与人工接管（审计 9.12）

当 SCADA 失联（进程崩溃、网络中断、桌面端关闭、数据库不可用）时，遵循以下原则：

1. **现场不停安全**：E-STOP、硬联锁、保护逻辑、SIF 照常工作（见第 2 节），不依赖 SCADA
2. **现场降级运行**：设备按 PLC 本地程序继续运行或按预定安全状态停机；操作员切换到现场 HMI / 就地控制 / 手动操作
3. **人工接管**：关键参数改由人工巡检与纸质/电子台账记录；控制操作改由现场授权人员就地执行，执行本单位的操作规程与唱票复诵制度
4. **不依赖记忆外推**：SCADA 失联期间，不得以失联前最后显示值作为操作依据；必须以现场仪表实测值为准
5. **恢复后补录**：SCADA 恢复后，失联期间的人工操作与异常事件按规程补录，审计链不留缺口

本系统的 HA 心跳（`core/ha_manager.py`）与断线重连（`RealDeviceManager.start_reconnect_loop`）仅改善可用性，**不构成**上述降级原则的替代品。
