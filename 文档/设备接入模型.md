# 设备接入模型：面向任意电气设备

> 目标：只要设备有一个**可读/可写的电气接口**（寄存器、线圈、HTTP、MQTT、
> OPC UA、厂商私有协议），就能用同一套模型接进来，而不是为每种设备写死逻辑。

## 1. 三层模型

| 层 | 配置 | 作用 |
|---|---|---|
| **设备身份** | `id / name / device_class / electrical / autonomy` | 这台设备是什么、铭牌参数、控制权归属 |
| **通信通道** | `protocol` + 协议字段（host/port/endpoint/topics/adapter） | 怎么读到它、怎么写它 |
| **点位映射** | `registers[] / nodes[] / topics[].points / adapter.points` | 电气量 ↔ 工程量的对应关系 |

三者解耦：同一台“三相电表”可以用 Modbus 接，也可以用网关 HTTP 接；
换协议只改“通信通道”，点位名和上层报警/看板不动。

## 2. `device_class` 与标准点位角色

`device_class` 是**语义标签**，不改变协议解析，但让模板、看板、审计能按类处理：

| 类别 | 典型设备 | 常见点位 |
|---|---|---|
| `sensor` | 温度/压力/液位/流量 | 测量值、单位、品质 |
| `actuator` | 接触器、电磁阀、继电器板 | 开关位、反馈位、手动/自动 |
| `drive` | 变频器、伺服 | 启停、频率/转速设定、电流、故障码 |
| `meter` | 电表、水表、气表 | 电压/电流/功率/电量、累计量 |
| `plc` | PLC、远程 IO | 控制字、状态字、寄存器区 |
| `relay` | 中间继电器、固态继电器 | 单 bit 输出/回读 |
| `hmi` | 触摸屏、网关 | 透传点位 |
| `other` | 其它 | 自定义 |

`electrical` 是铭牌参数（`rated_voltage` / `rated_current` / `phases` /
`power_type`），用于展示、量程合理性提示和审计，不参与协议编解码。

```yaml
device_class: meter
electrical: {rated_voltage: 380, rated_current: 100, phases: 3, power_type: ac}
autonomy: supervised
```

## 3. 四类接法（按设备能力选）

### 3.1 有 Modbus/PLC 接口

```yaml
- id: meter_line1
  name: 1# 进线电表
  protocol: modbus_tcp
  host: 192.168.1.31
  port: 502
  slave_id: 1
  device_class: meter
  autonomy: supervised
  registers:
    - {name: voltage_a, address: 0, data_type: float32, scale: 1, unit: V}
    - {name: current_a, address: 2, data_type: float32, scale: 0.1, unit: A}
    - {name: active_power, address: 4, data_type: float32, scale: 0.01, unit: kW}
    - {name: energy_total, address: 6, data_type: uint32, scale: 0.1, unit: kWh}
```

### 3.2 只有 HTTP 接口（网关/云平台/MES）

用 `protocol: custom` 的声明式映射：一个接口取一组点位，`records` 拆列表，
`path/type/enum/scale` 全部配置化。

```yaml
protocol: custom
adapter:
  transport: http
  base_url: "http://gateway.local/api"
  auth: {type: api_key, header: X-Key, value: "${GATEWAY_KEY}"}
  request: {path: "/devices/{device_id}/points"}
  response: {records: "data.items"}
  points:
    - {name: voltage_a, path: "ua", type: float, unit: V}
    - {name: run_state, path: "state", type: string,
       enum: {RUNNING: 1, STOPPED: 0, FAULT: -1}}
```

### 3.3 只有 MQTT（无线传感器/边缘网关）

```yaml
protocol: mqtt
host: 192.168.1.50
topics:
  - topic: factory/line1/meter
    device_id: meter_line1
    points:
      - {name: voltage_a, path: "ua", type: float}
      - {name: current_a, path: "ia", type: float, scale: 0.1}
```

### 3.4 私有协议 / 非标报文

在 `扩展/adapters/` 写插件，`transport: plugin`，实现 `read()` 即可；
详见 `插件适配器开发.md`。插件返回的点位仍进入同一套模型（历史库、报警、看板）。

## 4. 继电器/开关量设备的最小示例

一个 8 路继电器板（HTTP 接口，读回 `channels` 数组）：

```yaml
- id: relay_board_1
  name: 1# 继电器板
  protocol: custom
  device_class: relay
  electrical: {rated_voltage: 24, power_type: dc}
  autonomy: manual
  adapter:
    transport: http
    base_url: "http://192.168.1.60"
    request: {path: "/status"}
    response: {records: "channels"}
    points:
      - {name: ch1, path: "on", type: bool}
      - {name: ch2, path: "on", type: bool}
    write:
      method: POST
      path: "/channels/{name}"
      json: {on: "{value}"}
```

- 读：`ch1/ch2` 变成 1/0，进历史库与看板；
- 写：`write_point("ch1", True)` / `write_point("ch2", False)`；
- `autonomy: manual` 时，自动逻辑只能“提案”，人批准后才真正动作。

## 5. 选点原则

1. **一个电气量一个点位名**，不要用 `value1/value2`；点位名是报警/历史/看板的键；
2. `scale/offset` 只做“原始值 → 工程值”，不要在业务层再乘一次；
3. 状态量优先用 `enum` 映射成数值（`RUNNING: 1`），字符串状态不会进数值历史库；
4. 开关量用 `bool`（1/0），不要用 0/1 整数冒充模拟量；
5. 必填点位标 `required: true`，缺失时整次采集失败，避免“半套数据”；
6. 铭牌参数写 `electrical`，量程/报警阈值评审时有依据。

## 6. 接入检查清单

- [ ] `protocol` 与设备实际接口一致，且 `connect()` 能成功；
- [ ] 至少一个点位能读到**合理工程量**（不是原始寄存器值）；
- [ ] 写点位（如有）先设 `autonomy: manual` 验证，再切 `supervised`；
- [ ] 急停/联锁规则覆盖该设备的关键点位；
- [ ] `GET /api/devices` 显示 `connected=true`、`last_error` 为空；
- [ ] 历史库/看板能看到数据，报警规则能按点位名命中。
