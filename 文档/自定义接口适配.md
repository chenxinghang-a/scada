# 自定义接口适配（protocol: custom）

> 目标：对接一家第三方接口**不改代码**。请求怎么发、响应怎么拆、字段怎么映射，
> 全部写在设备配置的 `adapter` 段里。

## 1. 它和 `rest` 协议的区别

| | `rest` | `custom` |
|---|---|---|
| 请求粒度 | 一个点位一个 URL | 一个接口一组记录 |
| 响应结构 | 单值 + 一条 `json_path` | `records` 指定列表，逐点路径映射 |
| 字段类型 | 只当数值 | float / int / bool / string / auto |
| 枚举 | 不支持 | `enum: {RUNNING: 1, IDLE: 0}` |
| 写入 | 固定 `write_endpoint` | 可配 `method/path/body` 模板 |
| 认证 | none/basic/bearer/api_key | 同左（密钥支持 `${ENV}`） |

`custom` 适合 MES / IoT 平台 / 网关的"批量查询"接口；单点位 HTTP 仍可用 `rest`。

## 2. 最小示例

```yaml
devices:
  - id: mes_line1
    name: MES 产线接口
    protocol: custom
    enabled: true
    poll_interval: 5
    adapter:
      transport: http
      base_url: "https://mes.example.com/api/v1"
      auth:
        type: bearer
        token: "${MES_TOKEN}"          # 从环境变量取，别把密钥写进仓库
      request:
        method: GET
        path: "/lines/{device_id}/points"
        params: {detail: full}
        timeout: 5
      response:
        records: "data.points"         # 列表位置；不写则整个响应当一条记录
      points:
        - {name: temperature, path: "value", type: float, scale: 0.1, unit: "°C"}
        - {name: run_state, path: "state", type: string,
           enum: {RUNNING: 1, IDLE: 0, FAULT: -1}}
        - {name: pressure, path: "metrics.pressure", type: float, required: true}
```

对应的响应：

```json
{
  "data": {
    "points": [
      {"value": 500, "state": "RUNNING", "metrics": {"pressure": 0.82}}
    ]
  }
}
```

采集结果：`temperature = 50.0`（500 × 0.1）、`run_state = 1`、`pressure = 0.82`。

## 3. 字段表

### 3.1 `adapter`

| 字段 | 必填 | 说明 |
|---|---|---|
| `transport` | 否 | 目前只支持 `http` |
| `base_url` | 是 | `http://` 或 `https://` 开头 |
| `request` | 是 | 见 3.2 |
| `response.records` | 否 | 列表在响应里的路径；不写则整个响应视为一条记录 |
| `points` | 是 | 点位映射列表，不能为空、不能重名 |
| `write` | 否 | 反向写回，结构同 `request` |
| `poll_interval` | 否 | 轮询周期（秒），缺省用设备级 `poll_interval`，再缺省 5s |
| `auth` | 否 | 见 3.4 |

### 3.2 `request` / `write`

| 字段 | 说明 |
|---|---|
| `method` | GET / POST / PUT / PATCH / DELETE，默认 GET |
| `path` | 相对 `base_url`；也接受完整 URL。支持 `{device_id}`；`write` 额外支持 `{name}` / `{value}` |
| `params` | 查询参数对象 |
| `json` | 请求体（POST/PUT/PATCH）；支持占位符 |
| `headers` | 本次请求的附加头（会覆盖会话头） |
| `timeout` | 秒；缺省连接 3s / 读取 5s |

### 3.3 `points[]`

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 点位名（进历史库/报警规则的键） |
| `path` | 是 | 相对单条记录的取值路径，支持 `a.b[0].c` |
| `type` | 否 | `float` / `int` / `bool` / `string` / `auto`（默认 auto） |
| `unit` | 否 | 工程单位，落库与看板展示用 |
| `scale` / `offset` | 否 | `工程值 = 原始值 × scale + offset`，默认 1 / 0；`scale=0` 直接报配置错误 |
| `enum` | 否 | 原值 → 数值映射；大小写不敏感；未命中按坏值处理 |
| `required` | 否 | `true` 时该点缺失/坏值会让**整次采集失败**；默认只跳过该点 |

`type` 行为：

- `float`：必须是有限数值，NaN/Inf/字符串都拒绝；
- `int`：先转整数再套 `scale/offset`，结果取整；
- `bool`：接受 `true/1/on/yes` 与 `false/0/off/no`，输出 1.0 / 0.0；
- `string`：原样转字符串；
- `auto`：数值 → float（套 scale/offset），字符串 → 原样保留（状态文本）；
  布尔值按 1/0 处理。

### 3.4 `auth`

```yaml
auth: {type: none}
auth: {type: basic, username: "user", password: "${MES_PASSWORD}"}
auth: {type: bearer, token: "${MES_TOKEN}"}
auth: {type: api_key, header: "X-API-Key", value: "${MES_KEY}"}
```

`token` / `value` / `password` / `username` 都支持 `${ENV}`；变量不存在时
**启动即报错**，不会把字面量 `${MES_TOKEN}` 当密钥发出去。

## 4. 接入步骤

1. 编辑 `配置/devices.yaml`，加一台 `protocol: custom` 的设备（如上）。
   也可以在设备页选择「自定义接口 / 工厂插件」，粘贴 `adapter` JSON：
   - 「HTTP 模板」/「插件模板」生成骨架；
   - 下拉选择 `扩展/adapters/` 里的插件会自动补 `transport: plugin`；
   - 编辑已有设备时，页面通过 `GET /api/devices/<id>/adapter-config`
     取回**保留 `${ENV}` 占位符**的原文。
2. 热重载：`POST /api/devices/reload`（需要 engineer 及以上角色）。
   也可以重启进程。
3. 验证：
   - `GET /api/devices`：该设备 `connected=true`，`last_error` 为空；
   - `GET /api/data/realtime?device_id=mes_line1`：能看到点位值；
   - 服务端日志：`自定义适配器已连接: mes_line1（3 个点位）`。

## 5. 错误行为（为什么不是"静默成功"）

| 阶段 | 行为 |
|---|---|
| 配置解析 | 未知字段 / 重复点名 / 非法 scale / 缺环境变量 → `connect()` 返回 False，`stats.last_error` 写明具体字段 |
| 首次探测 | 请求成功但 `records`/`points` 路径对不上 → 连接失败（避免"采集成功但 0 个点"） |
| 运行期 | 单轮失败只记 `failed_requests` 并继续下一轮；熔断器打开时快速失败 |
| 点位缺失 | `required: false` 跳过该点；`true` 整次采集失败 |
| 数值异常 | NaN/Inf/布尔冒充数值 → 拒绝，不写进历史库 |

每次成功轮询会**整批替换**最新快照：接口里删掉的可选点位不会留下上一轮的旧值。

## 6. MQTT 主题也能用同一套映射（round 376）

`topics[]` 里写 `points:` 即可，字段与 HTTP 完全一致：

```yaml
- id: line_gateway
  name: 产线 MQTT 网关
  protocol: mqtt
  host: 192.168.1.50
  port: 1883
  topics:
    - topic: factory/line1/state
      qos: 1
      device_id: line1              # 可选：一个连接承载多台设备
      records: data.points          # 可选：载荷是列表时用它定位
      points:
        - {name: temperature, path: temp, type: float, scale: 0.1, unit: "°C"}
        - {name: run_state, path: state, type: string,
           enum: {RUNNING: 1, IDLE: 0, FAULT: -1}}
```

规则：

- 有 `points` 时**不再看** `json_path`/`name`（声明式优先）；
- 配置写错（缺 `path`、重名、`records` 非字符串）→ 该主题明确不采集并记 ERROR，
  **不会**回退成"按整包猜点位名"；
- 没有 `points` 的主题继续走旧的 `json_path + name`，存量配置不受影响；
- `device_id` 缺省用客户端绑定的设备 ID。

## 7. 配置校验

`配置/devices.yaml` 在启动/保存时会做两层校验：

1. JSON Schema（必填字段、协议枚举）；
2. `adapter` 语义校验（`records`/`points` 结构、scale、环境变量）——
   错误信息会直接指出是哪个设备、哪个字段。

## 8. 插件适配器（工厂自写代码）

声明式配置覆盖不了私有协议时，可在 `扩展/adapters/` 放一个 Python 插件：

```yaml
adapter:
  transport: plugin
  plugin: acme_mes
  settings: {url: "${ACME_MES_URL}", token: "${ACME_MES_TOKEN}"}
```

插件契约、热加载、安全边界见 **[插件适配器开发.md](插件适配器开发.md)**。

## 9. 已知限制

- HTTP 分页、登录换 token（OAuth2）暂未内置：用长期 token + `${ENV}` 注入。
- 多条记录映射到同名点位时**后一条覆盖前一条**；当前版本不支持动态点名。
- 写入只提供客户端方法 `write_point(name, value)`，尚未接入 `/api/control`
  的寄存器写入链路（该链路按地址/寄存器语义设计，急停/联锁/量程都基于地址）。
