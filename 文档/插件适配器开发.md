# 插件适配器开发指南

> 面向工厂自动化/集成商：在**不改主程序**的前提下，用一个 `.py` 接入私有协议、
> 第三方平台或本地计算逻辑。

## 1. 目录与加载

```
扩展/
  README.md
  adapters/
    example_mock.py     # 示例，可直接跑
    acme_mes.py         # 你的插件
```

- 默认从 `<项目根>/扩展/adapters/` 加载；
- 部署时可以用环境变量 `SCADA_PLUGIN_DIR` 指向工厂可写目录
  （升级主程序不会覆盖）；
- 插件名必须是合法 Python 标识符，加载路径做了父目录校验，`../` 会被拒绝；
- **插件以主进程权限运行，没有沙箱/超时强杀** —— 只部署可信代码。

## 2. 配置

```yaml
- id: acme_line1
  name: ACME MES 产线
  protocol: custom
  enabled: true
  poll_interval: 5
  adapter:
    transport: plugin
    plugin: acme_mes          # 对应 扩展/adapters/acme_mes.py
    settings:                 # 原样传给插件构造器，支持 ${ENV}
      url: "${ACME_MES_URL}"
      token: "${ACME_MES_TOKEN}"
    # 可选：插件返回原始载荷时，用 points 做映射（与 HTTP 适配器同规则）
    points:
      - {name: temperature, path: "data.temp", type: float, scale: 0.1, unit: "°C"}
```

约束：

- `transport: plugin` 不接受 `base_url/request/write/auth`（这些放 `settings`）；
- `response.records` 必须配合 `points` 使用；
- 没有 `points` 时，插件直接返回 `{点位: 值}` 或 `{点位: {value, unit}}`。

## 3. 插件契约

```python
PLUGIN_INFO = {
    'version': '1.0',
    'description': '对接 ACME MES',
    'author': '工厂自动化部',
    # 可选：给界面/工具用的配置说明（JSON Schema 形状，按需写）
    'settings_schema': {
        'type': 'object',
        'required': ['url'],
        'properties': {
            'url': {'type': 'string', 'title': '接口地址'},
            'token': {'type': 'string', 'title': '访问令牌'},
        },
    },
}

class Adapter:
    def __init__(self, settings: dict):
        self.client = MyHttpClient(settings['url'], settings['token'])

    def read(self) -> dict:                 # 必需（也可叫 poll）
        return self.client.get_points()

    def write_point(self, name, value):     # 可选，实现反向控制
        return self.client.set_point(name, value)

    def stop(self):                         # 可选（也可叫 close）
        self.client.close()
```

也可以导出工厂函数：

```python
def create_adapter(settings: dict):
    return MyAdapter(settings)
```

返回值约定：

| 情况 | 行为 |
|---|---|
| `read()` 返回 dict | 按 `{点位: 值}` 映射；数值/字符串/布尔都支持 |
| 配了 `points` | 返回原始载荷，由映射引擎按 path/type/enum/scale 解析 |
| `write_point()` 返回 `False` 或 `{'success': False}` | 记为写入失败 |
| 返回 `None` | 视为"无结论"，按成功处理（通知类插件） |
| `read()` 抛异常 | 该轮计失败，采集线程继续；`last_error` 可见 |
| 导入/初始化失败 | 该设备连接失败，其它设备不受影响 |

## 4. 开发与热加载

1. 复制 `扩展/adapters/example_mock.py` 改成自己的实现；
2. `GET /api/devices/adapters` 确认插件被列出（含 `version`/`description`/
   `settings_schema`，元数据用 AST 读取，**不会执行插件代码**）；
3. `POST /api/devices/adapters/reload` 断开插件设备并清模块缓存，
   下一轮采集重新加载（不用重启进程）；
4. `GET /api/devices/<id>/adapter-config`（engineer）读取配置原文，
   优先返回带 `${ENV}` 占位符的版本，适合回填到编辑界面；
5. `GET /api/devices` 看 `connected` 与 `last_error`；
5. 首次接入建议先用示例插件跑通链路，再替换 `read()` 实现。

## 5. 能拿到什么 / 拿不到什么

插件拿到的是 `settings`（配置里的 `adapter.settings`，`${ENV}` 已展开）；
它不直接依赖主程序的数据库/采集器，也不应该绕过统一入口写库。

推荐：

- 网络请求自己设超时（`requests(..., timeout=5)`）；
- 返回前把数值 `float()` 并处理 `None`；
- 大量点位/分页在插件内部处理完，`read()` 只返回最终点位；
- 需要离线演练时，用 `example_mock.py` 或返回固定值的桩插件。

## 6. 排障

| 现象 | 排查 |
|---|---|
| 设备 `connected=false`，`last_error` 含"插件不存在" | 文件名/插件名不一致，或 `SCADA_PLUGIN_DIR` 不对 |
| `last_error` 含"导入插件失败" | 插件顶层代码抛异常（语法/依赖） |
| `last_error` 含"必须实现 read()" | 类/工厂返回值没有 `read`/`poll` |
| 日志"声明式映射失败" | `points[].path` 与 `read()` 返回结构不一致 |
| 改了代码不生效 | 调 `POST /api/devices/adapters/reload`；确认断开了旧连接 |

## 7. 已知限制

- 插件进程内运行，**卡死的 `read()` 无法被强制中断**（Python 线程限制）；
  插件内部必须自己设网络超时。
- 插件写回目前只到客户端方法 `write_point`，尚未接入 `/api/control` 的
  寄存器安全链路（那条链路按地址/急停/联锁设计）。
- 插件目录不会热监听文件变化，改完需调用 reload 接口。
