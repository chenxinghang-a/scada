# 调研：开源实现（可用于工业设备模拟/仿真）

> 本文件由调研生成，用于指导「自研模拟器要不要引入开源件」的决策。
> 项目：`industrial_scada`（Python/Flask，已自研设备行为模拟器）。

## 一、候选清单

| 项目 | 覆盖能力 | 许可证 | 语言 | 与本项目集成的现实成本 | 结论 |
|---|---|---|---|---|---|
| **pymodbus `simulator`**（v3.8+，`pymodbus.simulator` + JSON datastore） | Modbus TCP/RTU **从站**；寄存器可按 JSON 定义、可运行时改值、可写回调 | **BSD-3** | Python | **低**：同语言，独立进程起一个从站，端口对得上即可 | **用**（见下） |
| asyncua（python-opcua 后继） | OPC UA **服务器** + 客户端；可动态建节点、订阅 | **LGPL-2.1** | Python | 中：需按信息模型建节点树 | 可选（需要真 UA 服务端时） |
| open62541 | OPC UA 服务器/客户端（C 实现，工业级） | MPL-2.0 | C | 高：需编译 + ctypes 绑定 | 只借鉴信息模型设计 |
| ModbusPal | Java GUI Modbus 从站，可画曲线 | **GPL-3** | Java | 中，但**传染性** | 不用 |
| diagslave | Modbus 主/从调试工具 | 免费闭源 | C | 低（当外部测试工具用） | 可作调试工具，不集成 |
| lib60870 | IEC 60870-5-101/104 库 | **GPL-3**（商业双授权） | C | 高 + 传染 | 不用 |
| libiec61850 | IEC 61850 库 | **GPL-3**（商业双授权） | C | 高 + 传染 | 不用 |
| OpenPLC | 软 PLC（梯形图 → 运行时） | **GPL-3** | C/Python | 高 | 只借鉴「状态机 + 扫描周期」思路 |
| Apache PLC4X | 多协议驱动（Modbus/S7/ADS…），含 `simulated` driver | **Apache-2.0** | Java | 高（JVM 依赖） | 不用（本项目已自研多协议） |
| ThingsBoard device simulator | MQTT 设备模拟（批量虚拟设备） | **Apache-2.0** | Java | 中 | 只借鉴「批量设备编排」 |
| EMQX | MQTT broker | Apache-2.0（5.x 部分 BSL） | Erlang | 低（当 broker） | 仅作 broker，不当模拟器 |
| Node-RED（工业节点） | 流编排 | Apache-2.0 | Node.js | 中，但架构不符 | 不用 |
| OpenModelica / FMU | 物理过程仿真（Modelica 语言） | OSMC-PL / GPL 混合 | Modelica | **很高**：要建模 + FMU 运行时 | 不用（成本远超收益） |

## 二、推荐结论

只引入 **1 个**：**pymodbus 的 simulator**。

理由：
1. 本项目模拟器是**进程内**的（`SimulatedModbusClient` 直接返回寄存器值），
   好处是快、可单测；坏处是**外部工具连不上** —— 用 Modbus Poll、
   PLC 调试软件、第三方 SCADA 做联调时，只能改代码打桩。
2. pymodbus simulator 能起一个**真 Modbus TCP 从站**，寄存器映射按 JSON 配。
   把现有 `devices_simulated.yaml` 的 address/name/data_type 导成它的 datastore，
   就得到一个「外部可连」的模拟现场，且**不改现有代码路径**（多一个进程而已）。
3. BSD-3 无传染风险；同语言；出问题能读源码。

**不引入** asyncua 的服务器模式：当前 OPC UA 模拟走的是「进程内生成数据」，
已经够用；真需要 UaExpert 浏览时再起一个 asyncua server 即可（10 行脚本级）。

**明确不用**：所有 GPL 类（ModbusPal / lib60870 / libiec61850 / OpenPLC）——
本项目的模拟器要跟主程序同进程/同仓分发，GPL 会传染整个后端。

## 三、引入 pymodbus simulator 的落地方式（不改主链路）

```
配置/devices_simulated.yaml
        │  导出（一次性脚本，P2 待实现）
        ▼
modbus_datastore.json（pymodbus simulator 的 datastore 格式）
        │
        ▼
pymodbus.simulator --json modbus_datastore.json --port 15020
        │
        ▼
真实 Modbus 主站（Modbus Poll / 第三方 SCADA / 现场调试软件）连 15020
```

这样「进程内模拟」（快、可测）与「对外真从站」（可联调）两条路并存，
互不影响 —— 符合本项目「成对路径必须等价」的既有约束（见
`tests/test_paired_path_guards.py`）。

**优先级：P2**。当前主链路（Web/采集/告警）不依赖它；它的价值在
「第三方工具联调」和「演示时给客户看真实 Modbus 报文」。
