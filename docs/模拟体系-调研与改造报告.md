# 模拟体系：调研与改造报告（round 340）

> 四条线并行调研（开源 / 模拟方案 / 厂家 / 接口），主线同步落地改造。
> 四份明细见 `docs/调研-*.md`；本文件是汇总与结论。

## 零、一句话结论

**模拟器的问题不是"数据不够真"，是"一半点位根本没有数据"。**
改造前 `devices_simulated.yaml` 30 台设备 **229 个点位有 136 个（59%）取不到值**，
客户端兜底 25.0 —— 界面上「有数」，实际是假的。
本轮把它变成 **42 台设备 / 316 点位 / 缺值 0**，且数值落在真实量纲内。

## 一、开源（详见 `调研-开源实现.md`）

| 项目 | 能力 | 许可证 | 结论 |
|---|---|---|---|
| **pymodbus `simulator`** | Modbus TCP/RTU **真从站**，JSON datastore，可运行时改值 | **BSD-3** | **唯一推荐引入（P2）** |
| asyncua | OPC UA 服务器 | LGPL-2.1 | 需要真 UA 服务端时再起（可选） |
| open62541 | OPC UA（C） | MPL-2.0 | 只借鉴信息模型 |
| ModbusPal / lib60870 / libiec61850 / OpenPLC | 各类模拟/协议库 | **GPL-3** | **不用**（传染整个后端） |
| Apache PLC4X | 多协议驱动（Java） | Apache-2.0 | 不用（JVM 依赖） |
| OpenModelica / FMU | 物理过程仿真 | OSMC-PL | 不用（建模成本远超收益） |

**为什么只推 pymodbus simulator（P2）**：现有模拟是**进程内**的，
外部工具（Modbus Poll / 第三方 SCADA / 现场调试软件）连不上。
它能起一个真从站，把 `devices_simulated.yaml` 的地址映射导出去即可，
**不改主链路**。优先级 P2：主链路不依赖它，价值在「第三方联调 + 演示」。

## 二、模拟（详见 `调研-模拟方案与设备缺口.md`）

### 2.1 本轮实际改造（已完成，非建议）

| # | 锁死点 | 改造前 | 改造后 |
|---|---|---|---|
| 1 | 参数名 → 数值是一张 **90 项硬编码表** | 表里没有的名字永远没数据 | 点位级 `sim` 段（`source/gain/offset/noise/min/max/decimals/dtype/map`）配置驱动 |
| 2 | 系数写死在表达式里（`mold_temp = temp*0.8`） | 改量纲必须改代码 | `gain/offset` 可配；支持**点位串链**（`出水 = 进水 + 5`） |
| 3 | 设备类型靠 **8 个 `elif '锅炉' in description`** 分支 | 新设备类型必须改代码 | 设备级 `simulation.process_model` 覆盖任意 `ProcessModel` 字段 |
| 4 | 监测设备靠**关键词猜测** | 「激光测厚仪」被误判成工作设备 | `simulation.monitoring` 显式声明 |
| 5 | 物理上限是**全局类常量** | 350 kW 冷水机被压成 **100 kW**、620 A 压成 **100 A** | `_calibrate_limits()` 按基准量放大 |
| 6 | `source: status` 输出 `DeviceState.value` | 运行时输出 **2**，而点表里 2 是**故障** | 映射成 `0=停机/1=运行/2=故障`，`map` 可覆盖；`status_raw` 留原值 |
| 7 | 基础版模拟器 **硬编码大端** | 配 CDAB 的设备读到 1.6e-38 这种荒谬值 | `encode_float32_registers()` 支持四种字节序，与增强版一致 |

第 6 条是最隐蔽的：**数字合法、语义反了** —— 所有正常设备在界面上显示「故障」，
真故障时输出 3 落到点表范围外被丢弃。

## 三、厂家（详见 `调研-厂家与仿真能力.md`）

**最重要的结论：厂家官方仿真器几乎都不能对外提供 Modbus / OPC UA 服务端。**

| 仿真器 | 能否被外部 SCADA 连上 |
|---|---|
| 西门子 PLCSIM / Advanced | Advanced 可多机互联，但**不提供 Modbus 从站** |
| 三菱 GX Works3 / 欧姆龙 Sysmac / 罗克韦尔 Emulate | **仅 IDE 内部**，不监听端口 |
| 发那科 ROBOGUIDE / 库卡 OfficeLite | 机器人本体仿真，**不开放现场总线** |
| **优傲 URSim** | **例外：免费，提供 Modbus TCP 服务端 + RTDE** |
| ABB Drive composer | 部分（变频器参数仿真） |

→ **自研模拟器 + 按真实点表复刻是唯一可行路线**；官方仿真器只能验证 PLC 程序。

**对接优先级**：P0 汇川 H5U / 台达 DVP / 施耐德 M340 / ABB ACS580 / 华为 SUN2000
（点表全公开）；P1 三菱 FX5U（MC）/ 欧姆龙 NJ（FINS）/ 西门子 S7-1500；
P2 中控 / 和利时（点表按项目交付）；P3 发那科 / 库卡 / 罗克韦尔（协议封闭）。

## 四、接口（详见 `调研-接口协议与限制.md`）

| 协议 | 必须可配的参数 | 最易错的三条 |
|---|---|---|
| Modbus | 字节序（ABCD/CDAB/BADC/DCBA）、地址基址（0-based vs 40001）、从站号、超时重试 | 一次读 >125 寄存器；**float32 字序真机不统一**；40001 当偏移发 |
| OPC UA | Endpoint、安全策略、NodeId 前缀（ns 索引随服务器变）、采样间隔、Deadband、QueueSize | **重连不重建订阅 → 假在线**；硬编码 ns=2；QueueSize=1 丢中间值 |
| IEC 104 | 公共地址、IOA 基址、K/W 窗口、t1/t2/t3 | IOA=0 非法；K 窗口溢出丢帧；总召未完成就发命令 |
| MQTT | QoS、retained、主题前缀、payload 格式 | QoS0 丢消息；retained 让新订阅者收到过期值 |
| MC 3E | 网络号/PLC 号/模块 IO/站号、ASCII vs 二进制 | CPU 监视定时器单位 250 ms；字/位软元件混用 |
| FINS | 节点号、内存区代码、TCP/UDP | **节点号必须唯一**；区代码 D/W/CIO/H 不可混 |
| REST | 鉴权方式、分页、限流 | 只看 HTTP 200 不看 body 里的 success |

**本轮已落地**：Modbus 字节序两套模拟器对齐（四种字节序编解码互逆，有测试锁住）。
**未落地（P2）**：OPC UA 重连后重建订阅的验证、IEC104 IOA 0 的拒绝。

## 五、待补齐与待解锁项（带优先级）

### 5.1 待补齐设备（P1，收益最高）

| 设备 | 理由 |
|---|---|
| 立体库堆垛机 | 与 `agv_system_01` 交接，仓储闭环缺这一环 |
| 除尘器本体（滤袋） | 现在只有引风机，没有「滤袋压差爬升→破袋→粉尘突升」的载体 |
| 消防泵 + 稳压泵 | 与 `fire_alarm_01` 联锁（喷淋→压力骤降→启泵）是消防验收必查 |
| 柴油发电机 | 市电失电 → UPS 支撑 → 柴发带载，这条链缺中间一环 |
| UPS 电池组（单体级） | 现在只有整组，缺「单体落后→整组容量↓→后备时间缩短」 |
| 模温机 | 注塑良品率的关键上游（模温→收缩率） |

### 5.2 待解锁的模拟能力（P1）

| 能力 | 现状 | 为什么值得做 |
|---|---|---|
| **日周期 / 班次阶跃** | 全天同一均值正弦 | 负荷、用气、用电、光伏辐照都应按 24h + 三班制变化；否则趋势图一眼假 |
| **离散事件计数** | 计数类用 `counter * gain` 线性增长 | 产量、批次、AGV 任务应是泊松到达的阶跃 |
| **守恒约束** | 各点位独立生成 | 进料=出料+在制品、P=ΣPφ、S²=P²+Q²、良品+废品=投入 |
| **渐进退化** | 故障多为瞬间跳变 | 轴承振动、刀具磨损、滤袋压差、电池内阻应随机游走 + 加速模型 |

### 5.3 待确认（需要主人/工艺拍板）

| 项 | 卡在哪 |
|---|---|
| `write_limits` 量纲 | 需要工艺负责人给每个点位的合法写入范围（0–150 °C 还是 −32768–65535） |
| 前端仓库路径 | `scada-app` 不在这台机器，阶段 0（GBK 编码）与 A1（端口劫持）做不了 |
| pymodbus simulator 是否引入 | P2，看是否需要「外部工具能连的 Modbus 从站」 |

## 六、怎么用（给后续维护）

```bash
# 体检：哪些点位拿不到值（改造前 59%，现在 0%）
python tools/sim_probe.py --gaps

# 看某台设备的实际数值范围（核对量纲）
python tools/sim_probe.py chiller_01 --rounds 10

# 定标：打印基变量实测值，决定 gain 该取多少
python tools/sim_probe.py compressor_01 --base
```

新增设备只需两步：
1. `配置/devices_simulated.yaml` 加设备与点表（地址、data_type、unit）
2. `配置/simulation_profiles.yaml` 加 `points`（source/gain/offset）

**不需要改代码** —— 这是本轮改造的核心目的。
