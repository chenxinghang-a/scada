# 多语言

两处语言能力：**安装包的语言选择**、**应用内的语言切换**。

---

## 一、检查结论：原来两处都缺

| # | 位置 | 原来的状态 | 严重程度 |
|---|---|---|---|
| 1 | 安装包 | `[Languages]` 只有 `chs` 一条 —— Inno **两条以上才出选择页**，所以从来没见过语言选择 | 高（用户第一眼就发现） |
| 2 | 安装包 | `[Tasks]` / `[Run]` / 卸载确认的文案是中文硬编码，即使切英文也还是中文 | 中 |

| 4 | 应用 | 模板 12 个文件约 **3011 处**中文硬编码，JS 约 **874 处**，无 `data-i18n` | 高 |
| 5 | 应用 | 设置页无语言选项，导航栏无切换入口 | 高 |
| 6 | 应用 | `<html lang>` 写死，`/api/i18n` 不存在 | 中 |

已补齐 1–6。

## 二、安装包：向导第一步选语言

`installer/scada.iss`：

```ini
[Languages]
Name: "en";  MessagesFile: "compiler:Default.isl"          ; 英文（Inno 自带）
Name: "chs"; MessagesFile: "lang\ChineseSimplified.isl"    ; 中文（仓库内置）
```

- **两条以上 → Inno 自动在向导第一步插入「选择语言」页**
- 顺序即默认项：英文在前 → 非中文系统默认英文；中文用户第一页就能切
- 所选语言记进注册表 `Software\SCADA\InstallerLanguage`，**升级和卸载沿用同一种语言**
- 自定义文案全部走 `[CustomMessages]` 双语（任务描述、完成页、卸载问句、残留报告）——
  漏一条就会在英文界面里冒出中文，所以每条都给了 `en.` 和 `chs.` 两份

> 为什么中文语言包要内置：Inno Setup 6.7.3 的安装目录 `Languages\` 里**没有中文**
> （只有日/韩/德/法等），官方把中文放在仓库的 `Unofficial/` 下。
> 写 `compiler:Languages\ChineseSimplified.isl` 会在别人机器上直接编译失败。

验证：

```powershell
# 英文安装 + 完全干净卸载
installer\verify_install.ps1 -Lang en -DeleteData

# 中文安装 + 保留数据卸载
installer\verify_install.ps1 -Lang chs
```

两条路径各 **20/20 通过**。

## 三、应用内：随时切换

### 3.1 入口

导航栏右上角「🌐 中文 / EN」下拉，**任何页面都能切**，切换立即生效（不刷新）。
选择存在 `localStorage`，刷新/跳页/换浏览器（同机）都保持。

### 3.2 实现

```
配置/i18n/zh-CN.json     42 条词条（中文原文）
配置/i18n/en-US.json     42 条词条（英文）
core/i18n.py             normalize / translate / bundle（带缓存）
展示层/api/api_i18n.py   GET /api/i18n/<lang>、GET /api/i18n
静态资源/js/i18n.js       按 data-i18n 替换 DOM
模板/base.html           导航 8 项加 data-i18n + 语言下拉
```

用法：

```html
<!-- 文本 -->
<span data-i18n="nav.dashboard">仪表盘</span>

<!-- 占位符 / tooltip -->
<input data-i18n-placeholder="btn.search">
<button data-i18n-title="label.language">
```

```javascript
// 动态文案（图表、表格里拼的）
window.scadaI18n.t('msg.no_data', '暂无数据')
document.addEventListener('scada:language-changed', function (e) {
    console.log('切换到了', e.detail.language);
});
```

### 3.3 语言选择顺序

1. `?lang=en-US`（URL 参数，调试用）
2. `localStorage`（用户在界面上选的）
3. `Accept-Language`（浏览器）
4. 默认 `zh-CN`

`/api/i18n` **不需要认证** —— 登录页就要显示正确语言，那时还没有 token。
词条里没有任何敏感内容（就是「保存」「取消」这类）。

## 四、边界：只翻「界面骨架」，不翻「数据」

模板里约 3011 处中文，其中**大部分不该翻译**：

| 类别 | 例子 | 翻不翻 |
|---|---|---|
| 界面骨架 | 仪表盘 / 保存 / 在线 / 暂无数据 | ✅ 翻 |
| 设备名、点位名 | `1号产线主控PLC`、`line_speed` | ❌ 不翻（现场填的，翻了对不上工单） |
| 报警内容 | `设备 compressor_01 通信失败 3 次` | ❌ 不翻（同上） |
| 报表/导出表头 | — | ✅ 应翻（当前未覆盖） |

**当前覆盖**：导航 8 项 + 常用按钮/状态/提示共 42 条。

**缺失的部分怎么处理**：`data-i18n` 找不到词条时**保留中文原文**，
不会变成空白或 `undefined`。这比「翻了 90%，剩下 10% 显示 undefined」安全得多。

### 补全流程

1. 给要翻译的元素加 `data-i18n="<语义 key>"`
2. 在 `配置/i18n/zh-CN.json` 加中文原文
3. 在 `配置/i18n/en-US.json` 加英文
4. 跑 `pytest tests/test_i18n_round350.py` —— 会校验**中英 key 集合一致**，
   漏一边直接红

## 六、已知限制

| 限制 | 原因 | 影响 |
|---|---|---|
| 报表/导出表头未翻 | 那部分文案在 Python 里拼（`export_*.py`），要走后端 `translate()` | 导出文件仍是中文表头 |
| 报警级别名（`critical`/`warning`）未翻 | 它们是枚举值，显示时直接输出英文原值 | 英文界面显示 `critical`，中文界面也显示 `critical` |
| 图表里的动态文案未翻 | `dashboard.js` 等直接拼中文 | 部分图表标题仍是中文 |
| 同时开两个标签页，一个切语言另一个不跟 | 没做 `storage` 事件广播 | 刷新即一致 |

补全顺序建议：**导出表头 → 报警级别 → 图表标题 → 其余**（按现场使用频率）。
